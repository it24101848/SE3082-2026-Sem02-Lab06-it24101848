============================================================ 1. SOURCE
CODE ============================================================

#include <omp.h> #include <stdio.h>

int main() { #pragma omp parallel { int th = omp_get_thread_num();

        printf("thread # %d\n", th);

        #pragma omp master
        {
            printf("Inside Master # %d\n", omp_get_thread_num());
            printf("Exiting Master\n");
        }

        printf("Hi again from thread # %d\n", omp_get_thread_num());
    }

    return 0;

}

============================================================ 5.
DESCRIPTION OF #pragma omp master
============================================================

#pragma omp master specifies that the associated structured block is
executed only by the master thread of the OpenMP team. The master thread
is thread 0.

In the actual results of this exercise, the line:

Inside Master # 0

appears in both the 2-thread and 4-thread executions. This confirms that
only thread 0 executed the master section.

Unlike the OpenMP single construct, the master construct does not have
an implicit barrier at its end. Therefore, the other threads do not have
to wait for the master thread to complete the master block before they
continue with their following statements.

This behavior is visible in the actual output. For example, in the
4-thread run, threads 3, 2, and 1 printed their “Hi again” messages
before thread 0 entered and completed the master section.

============================================================

Exercise 03 compiled and executed successfully on Amazon Linux using
