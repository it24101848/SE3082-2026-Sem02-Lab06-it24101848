============================================================ 1. SOURCE
CODE ============================================================

#include <omp.h> #include <stdio.h> #include <stdlib.h>

int fib(int n) { int i, j;

    if (n < 2)
    {
        return n;
    }
    else
    {
        #pragma omp task shared(i)
        i = fib(n - 1);

        #pragma omp task shared(j)
        j = fib(n - 2);

        #pragma omp taskwait

        return i + j;
    }

}

int main(int argc, char *argv[]) { int n = 20; int result = 0;

    if (argc > 1)
    {
        n = atoi(argv[1]);
    }

    double start = omp_get_wtime();

    #pragma omp parallel
    {
        #pragma omp single
        {
            result = fib(n);
        }
    }

    double end = omp_get_wtime();

    printf("Fibonacci(%d) = %d\n", n, result);
    printf("Threads = %d\n", omp_get_max_threads());
    printf("Execution time = %.6f seconds\n", end - start);

    return 0;

}

============================================================ 5.
DESCRIPTION OF OPENMP DIRECTIVES
============================================================

#pragma omp parallel

Creates a team of OpenMP threads. These threads are available to execute
the tasks generated during the recursive Fibonacci calculation.

#pragma omp single

Ensures that only one thread initially calls fib(n). Without this, every
thread in the parallel region could start its own complete Fibonacci
calculation.

#pragma omp task shared(i)

Creates an OpenMP task for calculating fib(n - 1). The variable i is
shared so that the result produced by the task is available when the
parent invocation continues.

#pragma omp task shared(j)

Creates another OpenMP task for calculating fib(n - 2). The variable j
stores the result of this task.

#pragma omp taskwait

Makes the current task wait until its directly generated child tasks
have completed. This is necessary before calculating i + j because both
Fibonacci results must be available.

============================================================ 6.
OBSERVATION ============================================================

Recursive Fibonacci exposes independent calculations, fib(n - 1) and
fib(n - 2), which can be represented as OpenMP tasks.

However, this implementation creates tasks recursively even for very
small Fibonacci calculations. For n = 20, the cost of creating,
scheduling, and synchronizing many small tasks is significant compared
with the actual computation performed by each task.

The measured results demonstrate this overhead:

1 thread = 0.001898 seconds 2 threads = 0.013218 seconds 4 threads =
0.013360 seconds

Therefore, more threads did not automatically provide better performance
in this experiment. Task creation and synchronization overhead dominated
the relatively small amount of useful computation.

Execution times can vary between runs depending on system scheduling and
other runtime conditions.
